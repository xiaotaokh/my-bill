# Supabase 反向代理部署与切换说明

## 一、背景

小程序原本直连 `https://scogsobcckvybkwcmvqh.supabase.co`。

2026-09-22 起，该域名在**中国移动**网络下被 TLS SNI 阻断：

- DNS 正常（解析到 Cloudflare 真实 IP，无污染）
- TCP 可连通（`curl` 显示 `Connected`）
- TLS 握手阶段被重置（`Recv failure: Connection reset by peer`）

表现为小程序 `wx.request` 报裸的 `{"errMsg":"request:fail"}`，登录拿不到 openid，
所有页面数据为空。电信 / 联通网络正常，所以排查时容易被误判为"服务器挂了"。

**结论：不是 Supabase 故障，也不是代码问题，是域名在网络层面的阻断。**

## 二、方案

用自建域名 + Cloudflare Worker 做一层反向代理，绕开被阻断的域名：

```
小程序 -> https://api.xiaotaokh.top (Cloudflare Worker) -> https://scogsobcckvybkwcmvqh.supabase.co
```

选它的原因：不用买服务器、不用备案、免费额度足够（每天 10 万次请求）。

## 三、部署步骤

### 1. 域名托管到 Cloudflare

1. 注册 Cloudflare 账号：https://dash.cloudflare.com/sign-up
2. `Add a site` -> 输入 `xiaotaokh.top` -> 选 Free 计划
3. 到注册商（阿里云）域名控制台 -> DNS 修改 -> 把 NS 换成 Cloudflare 分配的两个地址
4. 等待 Cloudflare 显示 Active（一般 1-2 小时，最慢 24 小时）

### 2. 创建 Worker

Cloudflare 控制台 -> `Workers & Pages` -> `Create application` -> `Start with Hello World!`
-> 命名 `mybill-api` -> Deploy -> `Edit code` -> 粘贴下面的脚本 -> Deploy。

注意：**不要勾选 Protect with Cloudflare Access**，否则会强制身份验证，小程序请求会被拦截。

```js
const UPSTREAM = 'https://scogsobcckvybkwcmvqh.supabase.co';

export default {
  async fetch(request) {
    const url = new URL(request.url);
    const headers = new Headers(request.headers);
    headers.set('Host', new URL(UPSTREAM).host);

    const init = { method: request.method, headers, redirect: 'manual' };
    if (request.method !== 'GET' && request.method !== 'HEAD') {
      init.body = request.body;
    }

    const resp = await fetch(UPSTREAM + url.pathname + url.search, init);

    const out = new Headers(resp.headers);
    ['content-encoding', 'content-length', 'transfer-encoding', 'connection']
      .forEach(h => out.delete(h));

    return new Response(resp.body, { status: resp.status, headers: out });
  },
};
```

### 3. 绑定自定义域名

该 Worker -> `Settings` -> `Domains & Routes` -> `Add` -> `Custom Domain`
-> 填 `api.xiaotaokh.top` -> 确认。Cloudflare 会自动创建 DNS 记录。

## 四、小程序切换

1. 修改 `utils/supabase.js` 顶部的 `SUPABASE_URL` 为 `https://api.xiaotaokh.top`。
   REST / Edge Functions / Storage 所有请求都基于这个常量，改一处即可。
2. 微信公众平台 -> 开发管理 -> 服务器域名 -> `request 合法域名` 新增：
   - `https://api.xiaotaokh.top`
   - `https://nf2vhfmeu7.re.qweatherapi.com`（天气接口，如未配置）
3. 历史图片地址刷库（见下节）。**必须等 Worker 验证通过后再执行**，否则图片会全部失效。

## 五、历史图片地址迁移

用户上传的头像、资产图标、分类图标在数据库里存的是完整 URL，含旧域名。
换域名后这些老图加载不出来，需要在 Supabase SQL Editor 执行：

```sql
update users      set "avatarUrl" = replace("avatarUrl", 'https://scogsobcckvybkwcmvqh.supabase.co', 'https://api.xiaotaokh.top') where "avatarUrl" like 'https://scogsobcckvybkwcmvqh.supabase.co%';
update categories set icon        = replace(icon,        'https://scogsobcckvybkwcmvqh.supabase.co', 'https://api.xiaotaokh.top') where icon        like 'https://scogsobcckvybkwcmvqh.supabase.co%';
update assets     set icon        = replace(icon,        'https://scogsobcckvybkwcmvqh.supabase.co', 'https://api.xiaotaokh.top') where icon        like 'https://scogsobcckvybkwcmvqh.supabase.co%';
```

预设头像（`data:image/svg+xml,...`）不受影响，无需处理。

## 六、验证命令

部署完成后，**在移动网络下**逐条验证（换成不存在的路径，不会污染数据，返回 JSON 即说明通了）：

```bash
# REST 读数据
curl -s "https://api.xiaotaokh.top/rest/v1/users?select=*&limit=1" -H "apikey: <ANON_KEY>" -H "Authorization: Bearer <ANON_KEY>"

# Edge Function（登录换 openid）
curl -s -X POST "https://api.xiaotaokh.top/functions/v1/get-user-openid" -H "apikey: <ANON_KEY>" -H "Content-Type: application/json" -d '{"code":"test"}'

# Storage 读取
curl -s -i "https://api.xiaotaokh.top/storage/v1/object/public/avatars/nonexistent.png" -H "apikey: <ANON_KEY>"

# Storage 上传
curl -s -X POST "https://api.xiaotaokh.top/storage/v1/object/nosuchbucket/t.txt" -H "apikey: <ANON_KEY>" -H "Authorization: Bearer <ANON_KEY>" --data-binary "hello"

# Storage 删除
curl -s -X DELETE "https://api.xiaotaokh.top/storage/v1/object/nosuchbucket" -H "apikey: <ANON_KEY>" -H "Authorization: Bearer <ANON_KEY>" -H "Content-Type: application/json" -d '{"prefixes":["t.txt"]}'
```

**关键判断**：返回 JSON（哪怕是 404 / 401 报错）就是通了；
出现 `Connection reset by peer` 或 `request:fail` 才是没通。

## 七、切回直连（备选方案）

**结论先行：即使日后中国移动恢复了对 `supabase.co` 的访问，也不建议切回直连。**
反代不影响任何功能，留着等于多一条后路。只有以下情况才值得考虑切回：

- 反代本身出问题（Cloudflare Worker 异常，或 `xiaotaokh.top` 也被阻断）
- 决定改用国内服务器 + 备案域名的方案
- 请求量超过每天 10 万次，且不想升级 Cloudflare 付费计划

### 7.1 切回步骤

1. 代码改回旧域名：
   - `utils/supabase.js` 的 `SUPABASE_URL` -> `https://scogsobcckvybkwcmvqh.supabase.co`
   - `scripts/clean-storage.js` 的 `SUPABASE_URL` -> 同上
2. 数据库反向刷一遍（新域名 -> 旧域名）：

```sql
update users      set "avatarUrl" = replace("avatarUrl", 'https://api.xiaotaokh.top', 'https://scogsobcckvybkwcmvqh.supabase.co') where "avatarUrl" like 'https://api.xiaotaokh.top%';
update categories set icon        = replace(icon,        'https://api.xiaotaokh.top', 'https://scogsobcckvybkwcmvqh.supabase.co') where icon        like 'https://api.xiaotaokh.top%';
update assets     set icon        = replace(icon,        'https://api.xiaotaokh.top', 'https://scogsobcckvybkwcmvqh.supabase.co') where icon        like 'https://api.xiaotaokh.top%';
```

   验证（三个数都应变成 0）：

```sql
select 'users' as tbl, count(*) from users where "avatarUrl" like 'https://api.xiaotaokh.top%'
union all
select 'categories', count(*) from categories where icon like 'https://api.xiaotaokh.top%'
union all
select 'assets', count(*) from assets where icon like 'https://api.xiaotaokh.top%';
```

3. 微信公众平台确认 `request 合法域名` 和 `uploadFile 合法域名` 里仍有
   `https://scogsobcckvybkwcmvqh.supabase.co`
4. Cloudflare Worker 可以留着不管，免费不影响
5. 开发者工具清缓存，重新验证登录、首页数据、上传图片、删除

### 7.2 注意事项

代码和数据库**必须同时改**。只改一边会导致请求域名和图片地址不一致：
代码走直连、图片地址却指向反代，或者反过来，排查问题时很容易被误导。

### 7.3 为什么不建议切回

- 直连是**被动**的：今天移动被封、明天可能电信跟进，被拦后只能干等运营商放行。
- 反代域名是**自己**的：真被拦了，照第三节再建一个 Worker、换个域名，
  十分钟就能恢复，主动权在自己手上。
- 切回还要再刷一遍历史图片地址（本次 319 条），多一次操作就多一次出错机会。

## 八、已知限制

- 这类阻断是动态的，新域名未来也可能被加入名单。届时重复第三节流程换个域名即可。
- Cloudflare Worker 免费版每天 10 万次请求，超出当天限流，次日恢复。
- 终极稳定方案是使用国内服务器 + 备案域名做反代，或迁回微信云开发（无需域名）。
